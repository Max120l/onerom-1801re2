# D22 — КР1801ВП1-055

The part the thermal fault was traced to, and what it actually is. Read from the
gate-array logic diagram, which turns out to be published.

## It is a bus transceiver

**A 16-bit bidirectional bus transceiver with inversion, plus three spare
non-inverting buffers.** Nothing more exotic than that.

| pins | signal | direction |
| --- | --- | --- |
| 1–8 | V0–V7 | bidirectional, internal side |
| 9–16 | W0–W7 | bidirectional, internal side |
| 22–29 | **Ā0–Ā7** | bidirectional, bus side, **inverted** |
| 30–37 | **Ā8–Ā15** | bidirectional, bus side, **inverted** |
| 20 | **Ā/WV** | direction select |
| 41 | **/OE** | output enable, active low |
| 38, 39, 40 → 17, 18, 19 | C0–C2 → A0–A2 | plain buffers, OE tied to ground, always enabled |
| 21 | GND | |
| 42 | VCC | +5 V |

Confirmed against the [1801BM1 project's page for this
part](https://github.com/1801BM1/k1801/tree/master/055), which describes it in
the same terms — "a bidirectional 16-bit buffer element, plus an additional
three-bit unidirectional buffer" — and gives the same pin assignments, with the
direction pin as nA/VW and the enable as nOE.

Pairing is V0↔Ā0 … V7↔Ā7 and W0↔Ā8 … W7↔Ā15. Each pair is a two-way path
through three `371` cells with a tri-state driver at each end; the `373`, `428`
and `429` network at the bottom of the diagram turns /OE and direction into the
per-side enables.

## The two halves are deliberately mismatched

**V0–V7 passes through three logic elements. W0–W7 passes through one.** It is
intentional — the delays are staggered so the two bytes do not switch together,
which cuts the peak current drawn from the supply. It is visible in the diagram:
three `371` blocks chained per bit in the left column, one in the right.

That asymmetry makes a prediction about how this part fails. **The V path has
roughly three times the propagation delay and therefore much less timing
margin**, so as delays stretch with temperature it should cross the threshold
first. V0–V7 pairs with Ā0–Ā7, which is the low byte of the AD bus.

So: **the low byte should fail before the high byte.** That is checkable with
`tools/make_regtest.py`, which writes sixteen-bit patterns to 177010 and reports
which bits come back wrong. Bits 0–7 failing while 8–15 stay clean would put the
cooling result, the proposed mechanism and the chip's own internal design in
agreement.

## Why that matters

**The MPI bus runs sixteen inverted AD lines.** That is the first thing stated in
`firmware/main.c`, and it is what the bars over Ā0–Ā15 mean. So D22 is the
transceiver between the machine's inverted AD bus and the peripheral processor's
internal bus — which puts it in the path of **every instruction the PP fetches
and every word it reads or writes**.

That is what makes the whole shape of this fault make sense:

- **Our data is correct at our pads and wrong when the PP decodes it.** The
  board's own drive check sampled the AD lines at the instant it asserted RPLY,
  on every served cycle, and was clean on every single reading — while the PP was
  plainly executing rubbish. D22 is the only thing between the two.
- **Nothing is ever stored wrong.** A transceiver is a pass-through, not a
  storage element. Every memory test, every register pattern, every retention
  check came back clean because none of them was ever testing the thing that was
  broken.
- **The slowest transfers fail first.** DRAM cycles have less timing margin than
  register transfers, so the PP's own RAM went before the plane ports did.
- **Cycles that never complete.** With the enable and direction derived from bus
  control including RPLY, a marginal turnaround misplaces the data window
  entirely — reads land at the wrong instant, or the cycle never finishes and the
  processor waits forever with no timeout to save it.

## A substitute from ordinary parts

A 16-bit inverting bidirectional transceiver with /OE and direction is **two
74x640s**. That is precisely what a '640 is — the inverting counterpart of the
'245 — and it maps one-to-one:

```
      74x640 #1                        74x640 #2
  A1..A8  <- V0..V7  (pins 1-8)    A1..A8  <- W0..W7  (pins 9-16)
  B1..B8  <- Ā0..Ā7  (pins 22-29)  B1..B8  <- Ā8..Ā15 (pins 30-37)
  DIR     <- pin 20                DIR     <- pin 20
  /OE     <- pin 41                /OE     <- pin 41
```

The three spare buffers (C1–C3 → A1–A3, always enabled) are three sections of a
'244 or any non-inverting buffer, outputs permanently on.

Notes for anyone building it:

- **Check the sense of DIR against the diagram before committing.** A '640's DIR
  chooses B→A or A→B; the gate array's Ā/WV has its own polarity, and getting it
  backwards gives a board that drives into the bus.
- **Faster logic is an advantage here, not a risk.** The failure being repaired
  *is* propagation delay, so ALS, F or ACT parts leave more margin than the
  original ever had. HCT is likely too slow.
- **The enable network is the real work.** /OE and direction come out of a
  `373`/`428`/`429` block in the original; a straight two-signal mapping is the
  starting assumption and should be verified against how the board actually
  drives pins 20 and 41.
- **Two identical '640s will not reproduce the deliberate V/W delay skew.** That
  skew exists to limit supply current transients, not for function, so the
  substitute should work — but it will draw a sharper current spike than the
  original, which is worth a decoupling capacitor of its own on the adapter.
- Mechanically this wants a small PCB in the original footprint with the two
  transceivers and the buffer on it.

None of that is trivial, but it is a weekend's work with catalogue parts — which
is a very different prospect from hunting a gate array that was only ever made
for Soviet PDP-11 clones.

## Sources

The logic diagram for КР1801ВП1-055 is published as a single-page vector PDF
titled with the part number, and the pin table above was read from it.

The [1801BM1 project](https://github.com/1801BM1/k1801/tree/master/055) has a
directory for this part with a die photograph, a symbolic diagram and a pin
description. It is an independent confirmation of everything above — the two
readings were done separately and agree — and it is the source for the
three-gate against one-gate delay figures, which the logic diagram shows but
does not quantify.
